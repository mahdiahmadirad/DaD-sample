# SPEC-0001: Provider-neutral text summarization

## Status

Approved

## Purpose

Define the first implementable text-analysis behavior for the sample: summarize submitted text without coupling feature code to a specific AI provider.

## Scope

- A provider-neutral application contract for summarization.
- One HTTP endpoint that accepts text and returns a summary.
- A deterministic local provider used as the default implementation.
- Validation for empty input.
- Automated verification of the provider and HTTP behavior.

## Out of scope

- External AI vendor integrations.
- Streaming responses.
- Authentication and authorization.
- Persistence of requests or summaries.
- Configurable summary styles or token limits.
- Failover across multiple providers.

## Requirements

- `REQ-001`: Feature code must depend on `IAIProvider`, not on a vendor SDK or vendor-specific type.
- `REQ-002`: `IAIProvider` must expose an asynchronous summarization operation accepting input text and a cancellation token.
- `REQ-003`: `POST /api/summaries` must accept JSON containing a `text` property.
- `REQ-004`: Blank or whitespace-only text must return HTTP 400.
- `REQ-005`: Valid text must return HTTP 200 with a JSON `summary` property.
- `REQ-006`: The default provider must run locally without secrets or network access.
- `REQ-007`: The local provider must produce deterministic output suitable for automated tests.

## Interfaces and behavior

### Provider interface

```csharp
Task<string> SummarizeAsync(string text, CancellationToken cancellationToken);
```

The interface expresses application behavior only. Provider-specific request objects, model names, SDK clients, and credentials must not cross this boundary.

### HTTP request

```json
{
  "text": "Text to summarize"
}
```

### HTTP success response

```json
{
  "summary": "Result returned by the configured provider"
}
```

### Local provider

The local provider returns the input unchanged when it contains 30 words or fewer. For longer input it returns the first 30 words followed by an ellipsis character. Its purpose is deterministic verification, not linguistic quality.

## Acceptance criteria

- The API project builds successfully.
- Tests prove blank input returns HTTP 400.
- Tests prove valid input returns HTTP 200 with a summary.
- Tests prove the local provider follows the deterministic 30-word rule.
- No feature/application source file references an external AI vendor SDK.
